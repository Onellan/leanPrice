# evaluate-agent-efficiency

**Trigger:** user asks to optimise coding agents, swarming, reasoning effort or workflow cost/speed.

Compare one changed agent/process variable with baseline on identical repository state, plan, acceptance and test context. Sample routine UI, price/offer integrity, SQLite/concurrency, safe scraping and ARM64 performance scenarios. Record whole run duration/tokens/repair cycles only when observable; unknown metrics remain unknown (not zero). Use independent code-review and test results as the quality oracle; a faster run that misses false-sale, SSRF or RAM defects is worse.

Reject lower-effort routing for high-risk PRICE/SOURCE/SEC/AUTH/DATA/CONC/PERF/DEPLOY work without a separately proven quality-equivalent gate and explicit approval. Never modify production instructions from one anecdotal result. Keep delivery metrics separate from software acceptance; no hosted CI or nonexistent local validator script assumed.

Output comparative table of scenario, quality-equivalence, repair cycles, available cost/time metrics, confidence and recommendation. Preserve risk-proportional agent context loads.
